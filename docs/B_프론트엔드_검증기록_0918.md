### 3-2. 백엔드 현재 상태 (에이전트가 확인)

- 8000 포트 리스너 없음, python/uvicorn 프로세스 없음 → 어제 세션의 백엔드는 이미 종료됨. **내릴 프로세스가 없고, 아직 GPT 호출도 발생하지 않았다.**
- 백엔드 폴더의 `.env`는 열지 않는다(팀 규칙: 프론트가 바꿀 수 있는 것은 프론트 저장소의 `VITE_API_URL` 한 줄뿐). `main.py:38`은 환경변수 `AGENT_MODE`를 읽고 기본값은 mock이며, `main.py:33`의 `load_dotenv`는 python-dotenv 기본 동작상 이미 있는 환경변수를 덮어쓰지 않는다. 따라서 **실행 전에 `$env:AGENT_MODE="mock"`을 주면 .env에 무엇이 있든 mock으로 뜬다**. 모드는 이 환경변수와 재기동 명령으로만 다룬다.
- 백엔드 `fixtures/mock_profile.json` = 프론트 `fixtures/mock_job_ready.json`의 `result` (바이트 동일). mock 모드는 이 파일을 그대로 돌려준다(`mock_agent.py`).
- **is_mock으로는 모드를 판별할 수 없다.** `profile_builder.py:156`이 llm 모드에서도 `is_mock: True`로 고정한다(가짜 입력 기반 실행이므로 테스트 표시 유지). 지시서 4절 항목 2와 일치.
- **문서 엔드포인트는 미구현.** `main.py:320-337`은 작업이 ready여도 항상 `409 {"error":{"code":"DOCUMENT_FAILED","stage":"rendering",…"아직 구현되지 않았습니다"}}`를 반환. 성공 응답의 헤더(위험 D·E)는 C가 구현한 서버에서만 확인 가능.
- uvicorn 기본 로그에는 모드가 출력되지 않는다(`main.py`에 모드 로그 없음).

### 3-4. 모드 확정 방법 (팀 공통기준 반영)

응답 특성(출처 파일명·상태 전이·is_mock)으로 mock/llm을 **추론하지 않는다.** 공통기준에 "가짜 자료로 실제 LLM을 호출해도 is_mock=true를 유지할 수 있다", "is_mock 배지만으로 실제 LLM 호출 여부를 판정하지 않는다"고 명시돼 있어 추론은 틀릴 수 있다.

모드는 **기동 시 환경변수로 명시해 확정**한다. 기록에 남길 근거는 다음 둘이다.

1. 기동 직전 같은 터미널에서 `$env:AGENT_MODE` 값을 출력한 결과("mock")
2. uvicorn 시작 로그(`Uvicorn running on http://127.0.0.1:8000`, `Application startup complete`)

주의: `main.py`에는 모드를 출력하는 로그가 없다(에이전트가 코드에서 확인). 따라서 시작 로그만으로는 모드가 보이지 않고, 1번의 환경변수 출력이 모드 근거다. 기동 터미널을 새로 열었거나 환경변수를 설정하기 전에 uvicorn을 실행했다면 근거가 되지 않는다.

`is_mock` 값은 모드 근거가 아니라 **화면 표시 확인용**(테스트 데이터 배지가 뜨는가)으로만 기록한다.

### 3-5-1. 환경변수 우선순위 확인 (기동 전 필수 확인, 에이전트가 코드로 확인)

- 백엔드에서 `.env`를 읽는 지점은 `main.py:34`, `agent.py:173`, `agent.py:419`의 `load_dotenv(ROOT / ".env")` 세 곳뿐이며 **모두 `override` 인자 없이 호출**한다.
- 설치된 python-dotenv 1.2.3의 `load_dotenv` 시그니처는 `override: bool = False`. 즉 **이미 설정된 환경변수는 .env 값으로 덮어쓰지 않는다.**
- `AGENT_MODE`는 `main.py:38`에서 모듈 import 시 `os.environ.get("AGENT_MODE", "mock")`으로 한 번만 읽는다. 셸에서 `$env:AGENT_MODE="mock"`을 준 뒤 같은 창에서 uvicorn을 실행하면 이 값이 그대로 쓰인다.
- mock 분기(`main.py:277` else)는 `mock_agent.get_mock_profile()`만 호출하며 `agent.py`(OpenAI 호출부)로 들어가지 않는다. `agent.py`의 `load_dotenv`도 llm 경로에서만 실행된다.
- 결론: **환경변수가 .env보다 우선. mock 지정 시 GPT 호출 경로에 진입하지 않음.**
