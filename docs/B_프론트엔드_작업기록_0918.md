## 3. 문의 1 — "Mock 결과 불러오기에서 파일을 넣으면 NEEDS_TEXT_SOURCE 오류가 뜬다"

- 화면에 뜬 문구는 `fixtures/mock_job_error.json`의 내용 그대로. 이 파일은 오류 응답이 결과로 오인되지 않는지 시험하는 용도라 오류만 뜨고 결과 영역이 비는 것이 설계된 동작(9/15 기록 2단계와 동일)
- 결과 화면이 바로 뜨는 파일은 `fixtures/mock_job_ready.json`
- Mock 로더 코드는 기존 React 저장소, 그 이전 바닐라 JS 프로토타입(`app.js`)과 같은 흐름이고 빌드 산출물도 동일하므로 두 저장소 동작이 다를 수 없음
- **코드 변경 없음**

## 4. 문의 2 — "회사소개서 생성을 누르면 `POST /api/profiles` 502 (Bad Gateway)"

**원인 (직접 확인)**

- 8000 포트를 듣는 프로세스 없음, python/uvicorn 프로세스 없음, `curl localhost:8000`·`127.0.0.1:8000` 모두 연결 실패
- Vite 프록시 대상(백엔드)이 꺼져 있으면 Vite가 502를 돌려주고, 응답에 `error` 객체가 없어 프론트는 `[UNKNOWN] 요청 중 오류가 발생했습니다.`로 표시 — `profiles.ts`의 설계대로 동작
- 9/15 기록과 같은 상황: 세션이 재시작되면 백그라운드 uvicorn이 함께 종료됨

**해결 방법 (사용자에게 안내)**

```powershell
cd "C:\Users\user\Downloads\FINAL_geosan_공용기준_0916\FINAL_geosan"
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

- 이 폴더 `.env`는 `AGENT_MODE=llm`이라 실제 GPT 호출. 고정 Mock만 보려면 실행 전 `$env:AGENT_MODE = "mock"`
- 백엔드를 띄운 뒤에도 502가 나면 `.env`를 `VITE_API_URL=http://127.0.0.1:8000`으로 바꾸고 `npm run dev` 재시작 (Node가 `localhost`를 IPv6 `::1`로 먼저 해석할 수 있는데 uvicorn은 IPv4만 들음)
- **코드 변경 없음**
