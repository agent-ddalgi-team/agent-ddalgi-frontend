# 배포 보안 확인표

기준일: 2026-10-12. 프론트 `05087f8`·백엔드 `2325d9a`의 코드 기준이다. 실제 운영 도메인·프록시·TLS·헤더를 검사하지 않았으며 아래 항목은 배포 완료 선언이 아니다. [현재 보안 구현](BACKEND_SECURITY_REQUIRED.md)과 함께 읽는다.

## 코드에서 확인한 범위

| 항목 | 확인한 사실 | 배포 시 확인할 것 |
|---|---|---|
| 빌드 | [vite.config.ts](../../vite.config.ts)에 sourcemap:false | 실제 dist 산출물·업로드 경로에 map/소스·비밀 파일이 섞이지 않는지 |
| 쿠키 | HttpOnly/SameSite=Lax, Secure는 OWNER_COOKIE_SECURE로 설정하며 기본 false | HTTPS 적용 후 Secure 설정과 실제 Set-Cookie 확인. 이번에는 .env를 읽거나 수정하지 않음 |
| API 연결 | Vite 개발 서버가 /api를 프록시함 | 정적 dist 배포에는 Vite 개발 프록시가 없음. 운영 리버스 프록시/동일 origin API 연결 필요 |
| 사진 크롤러 | Vite configureServer 플러그인에서 실행 | 정적 배포로 운영 크롤러가 생기지 않음. 별도 서비스·접근/호출 제한·아웃바운드 경계 설계 필요 |
| CORS | 백엔드가 FRONTEND_ORIGINS 설정을 사용 | 운영 origin 목록 확인. 브라우저 CORS를 로그인/권한 검사 대용으로 사용하지 않음 |
| 보안 헤더 | 일부 파일 응답에 no-store/nosniff 등 개별 헤더 있음 | 전 응답용 CSP/HSTS/프레임 정책을 설정한 배포 파일은 현재 저장소에서 확인 못함 |
| 외부 자원 | [index.html](../../index.html)이 Google Fonts를 사용; 이미지/다운로드/프록시 경로가 별도 존재 | 실제 사용하는 origin과 blob/data 자원을 조사해 CSP를 정하고 미리보기·사진·PDF 기능 회귀 확인 |

## 운영 환경에서 별도로 확인할 항목

1. **공개 경로:** 정적 파일은 dist 범위로 제공한다. 저장소 루트·.git·.env·docs·scripts·백엔드 private_runs를 정적 배포 경로에 포함하지 않는다. public에 놓인 파일은 공개용으로 판단한다.
2. **HTTPS/쿠키:** 운영 인증서·리다이렉트·프록시 TLS 종료 구성을 확인하고 실제 응답 쿠키를 점검한다. HSTS의 적용 범위/기간·하위 도메인 포함·preload는 운영 도메인 조건을 확인한 뒤 결정한다. 옛 문서의 2년/preload 예시를 그대로 적용하지 않는다.
3. **응답 헤더:** HTML/정적/API별 CSP, frame-ancestors 또는 프레임 제한, nosniff, Referrer-Policy, 필요한 Permissions-Policy를 검토한다. 기존 도메인 나열식 CSP 예시는 현재 네트워크 요청과 일치한다고 검증되지 않아 제거했다. 변경 후 실제 브라우저에서 기능과 차단 로그를 확인한다.
4. **부하·파일 처리:** 프록시 요청 크기·시간·동시성, 사용자/IP 호출 제한, 크롤러/파서 실행 자원, AI 비용 통제를 별도로 설정·검증한다. 앱의 파일당 크기 제한이나 시험용 AI 예산 설정만으로 전체 방어를 대체하지 않는다.
5. **캐시·오류:** 세션별 원문/문서/출력의 공유 캐시 여부를 점검한다. 원본/내보내기 경로의 no-store 적용과 오류 응답의 내부 경로/비밀값 노출 여부를 실제 응답으로 확인한다. 해시 정적 파일과 개인 API 응답의 캐시 정책은 분리한다.
6. **자료 보관:** DB·등록 원문·백업·브라우저 편집 사본의 접근/보존/삭제 정책을 정한다. 서버 세션 정리가 백업·브라우저 사본까지 자동 제거한다는 뜻은 아니다.
7. **출력 경로:** 배포 승인 전에 즉시 PDF가 서버 승인 출력과 혼동되지 않도록 SEC-01을 처리한다. 프론트 버튼 클릭만으로 서버 승인 이력이 생기지 않는다.

## 배포 검수 기록 방식

배포 담당자는 적용 환경·커밋·실제 응답 헤더·권한/만료/파일 검사 결과·남은 항목을 기존 [WORK_SUMMARY](../WORK_SUMMARY.md)에 기록한다. 비밀값·쿠키·실회사 원문을 문서에 복사하지 않는다. 이번 작업은 코드와 문서의 정합성 확인이며 배포 시험·취약점 전수 감사·유료 AI 호출은 하지 않았다.
