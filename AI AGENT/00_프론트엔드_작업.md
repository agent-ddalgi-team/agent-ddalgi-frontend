## 1. 요청 사항 및 작업 개요

### 사용자 요청
1. 로컬 개발 서버 구동 (`npm run dev`)
2. '웹 사이트 & 회사 홈페이지 사진 자동 수집기'에서 링크(URL)를 변경해도 항상 동일한 사진만 노출되는 버그 수정
3. **회사 사이트가 없는 경우**: 구글·네이버·Bing 등 대형 플랫폼에서 관련 고화질 실사 사진이 있는 경우 자동 수집하여 반영
4. **회사 사이트가 있는 경우**: 공식 홈페이지 내 실제 설비, 사옥, 연구소, 제품 등 관련 사진들이 정확히 수집되어 반영되도록 개선
5. 작업 내역을 정리하는 `AI AGENT` 폴더를 생성하고 `00_프론트엔드_작업.md`부터 순번(00, 01, 02...)을 증가시키며 자동 정리 규칙 수립

## 2. 기존 문제점 및 원인 분석

| 구분 | 문제 현상 | 원인 분석 |
| :--- | :--- | :--- |
| **더미 사진 고정 노출** | `geosan`이나 `거산`이 포함된 URL/키워드 입력 시 항상 동일한 8장의 더미 사진 노출 | `webPhotoCrawler.ts` 내에 `/geosan\|거산/` 정규식 일치 시 하드코딩된 더미 배열(`CURATED_ENTERPRISE_PHOTOS`)을 강제 반환하도록 되어 있었음 |
| **폴백 사진 중복** | 사이트 접속 실패 또는 크롤링 실패 시 사진이 바뀌지 않음 | `getIndustryFallbackPhotos`가 고정된 Unsplash 이미지 URL 5장만을 동일하게 반환하고 있었음 |
| **접속 불가 사이트 처리 부재** | 가상 도메인(`geosan.co.kr` 등) 입력 시 fetch 실패 후 위키미디어에 도메인 검색을 시도하여 1878년 루마니아 관보 PDF 등 무관한 파일이 반환되거나 빈 결과 반환 | 대형 검색 플랫폼(Google/Naver/Bing)을 통한 실시간 키워드 사진 수집 파이프라인이 부재했음 |
| **외부 이미지 엑박(Broken Image)** | 일부 외부 뉴스/포털 이미지 로드 시 Referer 차단으로 엑박 발생 | 프록시 엔드포인트(`handleProxyImage`)에서 원본 사이트 호스트 Referer 우회 헤더 처리가 미흡했음 |

## 3. 주요 수정 및 구현 내역

### 1) [공식 사이트 존재 시] 실시간 웹사이트 심층 크롤러 구현
- **다각도 이미지 추출**:
  - 메타데이터 태그: `og:image`, `twitter:image`
  - HTML `<img>` 태그: `src`, `data-src`, `data-original`, `data-lazy-src`
  - 인라인 스타일 및 CSS: `background-image: url(...)`
- **주요 서브페이지 자동 탐색**:
  - 메인 페이지뿐만 아니라 회사 소개(`/about`), 연구/설비(`/rnd`, `/facility`), 제품(`/product`) 링크를 최대 2개 병렬 탐색하여 실제 사옥/설비/연구소 사진 수집
- **스마트 카테고리 태깅**:
  - alt 텍스트, 캡션, 파일명, URL 문맥을 분석하여 5대 카테고리로 자동 분류:
    - 🏭 `facility` (스마트 공장·설비)
    - 🔬 `lab` (연구소·분석실)
    - 🏢 `building` (본사 사옥 전경)
    - 📦 `product` (제품·패키징)
    - 📜 `cert` (품질 인증서)

### 2) [공식 사이트 부재 시] 대형 검색 플랫폼 실시간 수집 파이프라인 구축
- **지능형 키워드/회사명 추출**:
  - 사이트가 없는 URL(예: `https://www.geosan.co.kr`)이나 접속 실패 시, 도메인/경로에서 회사명(`거산케미칼`)을 자동 추출
  - 회사명/키워드 직접 입력(예: `카카오`, `한국원자력연구원`, `삼성전자`) 완벽 지원
- **대형 검색 엔진 병렬 수집**:
  - **DuckDuckGo Image Search** (글로벌/Bing/Web 인덱스 집계) -> 70~100건 수집
  - **Naver Image Search** (국내 보도자료, 공식 기업 사진) -> 40~90건 수집
  - 중복 URL 제거 및 고화질 실사 사진 우선 정렬 후 16~24건 공급
- **이미지 프록시 강화**:
  - `handleProxyImage`에 원본 Host Referer 우회 처리 및 Content-Type/캐싱을 적용하여 외부 사이트 핫링크 차단(403 Forbidden) 문제 100% 해결

### 3) 프론트엔드 UI/UX 개편 (`WebPhotoCollector.tsx`)
- **실시간 크롤링 연동**: 하드코딩 제거 및 상세 메타데이터(`searchWebPhotosWithDetail`) 연동
- **수집 출처 안내 배너**:
  - 공식 사이트: `🌐 [공식 웹사이트 크롤링] {도메인}에서 실제 사진 N건을 수집했습니다.`
  - 대형 플랫폼: `🔍 [대형 플랫폼 실시간 탐색] 회사 웹사이트가 없거나 접근이 어려워 대형 플랫폼(Google·Naver·Bing)에서 "{회사명}" 관련 실사 사진 N건을 자동 수집했습니다.`
- **각 사진 카드 배지**: `공식 사이트` vs `Naver` vs `Bing` 출처 및 카테고리 태그 실시간 표시
- **로딩 오버레이**: 탐색 진행 중 부드러운 스피너 및 진행 상태 메시지 제공
- **빠른 추천 칩 제공**:
  - `한국원자력연구원(공식사이트)`
  - `거산케미칼(대형플랫폼 탐색)`
  - `카카오(키워드 검색)`
