## 3. 프론트엔드 문제 해결 및 수정 내역 (Frontend 범위 한정)

백엔드 소스코드(API, model, service, router, config, migrations)는 **READ-ONLY 원칙을 100% 준수**하여 전혀 수정하지 않았으며, 모든 연동 및 화면 처리는 프론트엔드 코드베이스에서 해결했습니다.

### 1) 자료 충족도 계산 폴백 연동 (`SourceSelectionView.tsx`)
- **문제 현상**: 백엔드 사전 점검 응답에서 `sufficiency` 객체가 `null`로 반환될 경우 화면의 "자료 충족도 00%" 영역이 비정상 표시됨.
- **해결 내역**: `computeSufficiency(ai.preflight)` 유틸리티 함수를 구현하여, 백엔드가 `sufficiency`를 직접 계산해 주지 않더라도 `preflight.facts`의 지지 상태 및 `preflight.issues`의 블로커 유무를 기반으로 4개 핵심 카테고리(회사 개요, 주요 사업/제품, 기술/공정, 강점/차별점)의 충족도(25% 단위 4단계)를 정확하게 산출하도록 보완.

### 2) 미설정 공개 데이터 자동 수집 에러 대응 (`useSources.ts`)
- **문제 현상**: 공공데이터 포털 등 외부 API 키가 미설정된 환경에서 "공개 데이터 자동으로 가져오기" 클릭 시 404/503 오류가 발생하면서 세션 상태가 불일치될 위험.
- **해결 내역**: 백엔드 커넥터 미설정 에러(404, 503)를 정밀 포착하여 `PUBLIC_DATA_NOT_CONFIGURED` 코드와 함께 `"외부 API 키와 수집 연결을 아직 설정하지 않았습니다."` 사용자 친화적 메시지를 반환하고 불필요한 상태 변이를 차단.

### 3) 동일 입력 재점검 시 영향 검토(Impact Review) 상태 머신 개선 (`usePublication.ts`, `DocumentWorkspace.tsx`)
- **문제 현상**: 이전 변경 영향(Impact Review)을 적용하여 문서 개정이 완료된 후, 동일한 입력 세션에서 "자료 변경 시작" -> "변경 자료 AI 점검"을 재실행하여 새 사전 점검(Preflight)이 생성되었을 때, 2단계 문서 편집 화면에서 최신 점검 확인 체크박스(`aria-label="최신 점검 확인"`)가 활성화되지 않던 상태 불일치 현상.
- **해결 내역**:
  - `usePublication.ts`의 `Saved` 상태에 `boundPreflightId`를 추가하여 문서에 결합된 사전 점검 ID를 추적.
  - 새 사전 점검이 감지되었을 때(`newPreflightDetected`), `impactRequired`를 올바르게 활성화.
  - 과거에 이미 적용 완료(`status: 'applied'`)되었던 구버전 영향 검토 결과를 새 점검 진입 시 안전하게 정리하고, 최신 점검 확인 체크박스 및 "변경 영향 불러오기" 버튼이 정상 노출되도록 개선.
  - `DocumentWorkspace.tsx`에서 stale 상태를 포함하여 `impactPanel` 렌더링 조건을 동기화.

### 4) 코드 품질 및 린트 정화 (`documentExport.ts`)
- ESLint `prefer-const` 규칙 위반 및 정규식 제어 문자 미이스케이프 경고 해결.
