# 프론트 문서·작업 기록 규칙

기준일: 2026-10-12. 사용자의 문서 통합 요청에 따라 이전 번호별 MD 자동 생성 규칙을 대체한다.

## 현재 기준과 경로

- 실행·폴더 안내: `README.md`
- 현재 상태·남은 일·새 작업 기록 원본: `docs/WORK_SUMMARY.md`
- 현재 보안 구현·배포 확인표: `docs/security/`
- 발표·시안·샘플 참고: `docs/reference/`
- 과거 기록 보관: `docs/archive/` (본문의 옛 지침·미구현 가정을 현재 규칙으로 실행하지 않는다)
- API 계약 원본: 별도 백엔드 저장소의 `docs/contracts.md`. 프론트에 새 사본을 만들지 않는다.

## 기록 방법

1. 새 작업마다 번호 MD·일일 요약·노션 요약·인계 문서를 자동 생성하지 않는다.
2. 기존 WORK_SUMMARY의 현재 상태/남은 일을 먼저 갱신하고 4절에 날짜·요청·변경 파일/목적·실제 검증 결과·한계·다음 일을 간결하게 누적한다.
3. 결정/보안 사항은 해당 원본 문서에서 수정하고 작업 기록에서는 링크로 연결한다. 같은 내용을 여러 문서에 복제하지 않는다.
4. 오래된 완료 기록은 필요할 때 기존 `docs/archive/WORK_HISTORY.md`로 옮긴다. 현재 상태·미해결 과제·코드 근거는 보관 기록에만 묻어 두지 않는다.
5. 별도 새 문서가 꼭 필요한 경우에만 목적·위치·기존 문서로 해결하기 어려운 이유를 설명하고 사용자 확인 후 생성한다.
6. 실제 코드·문서·검증 결과가 다르면 구현/제안/과거 기록을 구분한다. 미실행 확인이나 가상 검사를 실제 보안/AI 품질 성공으로 표시하지 않는다.
7. 문서 이동·통합 때 README·상대 링크·파일 목록·사용 스크립트의 경로를 함께 수정한다. 비밀값·쿠키·실회사 원문은 기록하지 않는다.
